# Case Study: AI Application Developer & Automation Engineer

## Timebox

~1.5 tp 2 hours of work.

Do not polish. We evaluate approach and clarity, not features.

This is a throwaway exercise. We are not using your code for anything.

---

## What to build

A web application that scores a vendor profile against a stored RFQ
(Request for Quotation).

**Flow:**

1. App stores multiple RFQs in a database. Seed it with the three provided.
2. User selects an RFQ from a dropdown.
3. User uploads or pastes a vendor profile.
4. Backend invokes an AI agent that evaluates the profile against the RFQ.
5. UI displays: an alignment score out of 100, three supporting reasons,
   and two gaps.
6. Past evaluations are listed below, most recent first.

---

## Tooling

Entirely your choice. Frontend framework, backend language, database, LLM
provider, agent framework (or no framework — direct API calls with tool use
are fine). Use whatever you are fastest in. Free tiers are fine.

SQLite or a local Postgres is plenty. Do not spend time on hosted infra.

You may use any AI coding assistant. We expect you to. In the follow-up
interview we will ask you to modify this code live and explain your choices,
so make sure you understand what you have built.

## Deliverables

Five things. The first four are required.

**1. A public GitHub repo**
Containing the working application.

**2. A README that works**
Setup steps, environment variables needed, how to load the seed data, how to
run it. We will follow it on a clean clone. If a step is missing, the app does
not run.

**3. `BUILD_LOG.md` in the repo root**
Use the provided template. This is read as carefully as the code.

**4. Commit history**
At least 5 meaningful commits. No single squashed "initial commit". Messages
should describe intent, not mechanics.

**5. Your AI session transcript — optional**
Attach or link it if you are comfortable. We are interested in how you work
with these tools, not checking up on you.

### Also required

- Secrets in environment variables, never committed to the repo
- Seed data loads via a documented command or on first run

---

## Constraints

- Single-page interface, no routing
- No authentication, no deployment required
- Vendor profile input accepts free text (or the provided sample files)
- One LLM call per evaluation

---

## Out of scope

RAG, vector stores, multi-agent orchestration, ranking multiple vendors
against each other, styling beyond legible, test suites, CI/CD.

Document parsing edge cases — all sample files are plain text.
